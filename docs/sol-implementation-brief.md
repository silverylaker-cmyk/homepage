# Sol 구현 작업 지시서

상태: 후속 코딩 작업용. 현재 턴에서는 기획 문서만 작성했다.

## 작업 맥락

사용자는 신규 이비인후과 의원 홈페이지를 만들고 결과물을 `homepage` 저장소에 푸시하기를 원한다. 기획은 먼저 제시하고, 실제 코딩은 Sol 모델이 수행한다.

- 작업 위치: `/Users/jiho/orca/homepage`
- 원격: `https://github.com/silverylaker-cmyk/homepage/`
- 먼저 읽을 문서: `docs/website-plan.md`, `docs/reference-review.md`
- 자료 원본: `/Users/jiho/mydrive/이비인후과 홈페이지 기획/`
- 계획 이후 사용자가 전달하는 의원 정보·수정 지시가 가안보다 우선한다.

## 사용자 확정 사항

- 이름: 알지 이비인후과. 지역: 신매역. 상세 주소와 법정 명칭은 미확정.
- 중점 분야: 만성·알레르기 비염, 난청·이명, 두경부 종양. 세 번째 명칭은 사용자에게 확인 완료. 제공 검사·수술·암 치료 범위는 별도 확인하며 임의로 확장하지 않는다.
- 디자인: Anthropic 홈페이지 같은 현대적인 느낌. 기존 네이비·청록 가안은 폐기한다.
- 준비 자료 없음. 실존하지 않는 프로필·시설·장비 정보로 채우지 않는다.
- 예약: 네이버 예약. 카카오채널은 초기 범위에서 제외.
- 개원일·운영 담당 미정. 현재 요청은 기획 정리이며 실제 코딩은 후속 단계에서 수행한다.

## 구현 요청

1. 레포 상태와 최신 지시를 확인하고 Next.js + TypeScript 기반 프로젝트를 설정한다. 정적 페이지 생성 중심으로 구현한다.
2. 우선 홈과 공통 컴포넌트를 완성하고 모바일·데스크톱에서 확인한다. Anthropic을 참고한 아이보리·먹색, 큰 한글 제목, 넓은 여백, 얇은 구분선과 절제된 그래픽을 적용한다. 사진 없는 메인도 완성된 화면으로 디자인한다.
3. 계획의 라우트와 데이터 구조를 구현한다. 의원명·전화·주소·시간·외부 링크는 한 곳에서 관리한다.
4. 모바일 탐색, FAQ, 비급여 검색, 일정 상태를 구현한다. 진료 상태는 일정 기준으로 계산하며 데이터가 불충분하면 표시를 생략한다.
5. 미확정 정보는 콘텐츠 데이터에서 명시적으로 관리한다. 가상의 학력·경력·장비·가격·후기를 작성하지 않는다. 공개 준비가 되기 전에는 검색 노출을 막는다.
6. 외부 네이버 예약·지도는 실제 URL 확보 후 연결한다. 원본 시안의 `#` 링크, 고정 ‘진료 중’, 기획자용 문구를 그대로 남기지 않는다.
7. 초기에는 자체 예약·문진·문자·자가진단 백엔드를 추가하지 않는다. 건강정보는 승인된 원고만 공개한다.
8. 소재별 원본 링크·라이선스·변경 여부를 기록한다. 의료진 사진과 시설 사진은 실제 자료를 사용한다.
9. 빌드·타입·린트, 링크·키보드·반응형·비급여 검색을 확인한다. 일정 계산은 경계값 테스트로 확인한다. 실행 명령, 콘텐츠 수정·배포 절차, 남은 입력사항을 README에 작성한다.
10. 변경사항을 검토하고 커밋·푸시한다. 공개 배포는 도메인·호스팅과 실정보 확정 단계로 구분해 보고한다.

## 인수 조건

계획의 완료 기준을 충족하는 실행 가능한 사이트와 재현 가능한 실행·빌드 명령이 있어야 한다. 구현 범위, 검증 결과, 화면 확인 결과, 남은 실정보, 커밋 및 푸시 결과를 보고한다. 확보하지 못한 정보나 검증하지 못한 동작은 명시한다.
